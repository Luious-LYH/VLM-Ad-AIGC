一、v0.1 必须跑通的流程

商品 PNG/JPG + 用户 Prompt
→ 参考商品 mask
→ VLM 商品理解和可选 Prompt 润色
→ product.json / intent.json / storyboard.json
→ SDXL+IP-Adapter 或 FLUX.2-klein 关键帧
→ 关键帧商品分割
→ LTXV-2B distilled 或 Wan2.2 TI2V-5B 视频
→ 视频商品 mask 跟踪
→ 商品一致性、文本匹配、Storyboard、时序和工程性能评测
→ manifest.json、metrics.json、report.md、mask overlay 和证据帧

二、保留模型

VLM：
- Qwen3-VL-4B-Instruct
- InternVL3.5-8B-HF

图像：
- SDXL 1.0 + IP-Adapter
- FLUX.2-klein-4B

视频：
- LTXV-2B distilled
- Wan2.2 TI2V-5B

HunyuanVideo 保留历史代码和产物，但不进入 v0.1 默认实验。

三、分割与跟踪

1. 输入 PNG 有有效 Alpha 时，直接将 Alpha 作为参考商品 mask。
2. 无 Alpha 时优先 smoke test SAM 3.1，使用文本或 exemplar 提示得到商品 mask。
3. SAM 3.1 因权重权限、环境或稳定性无法运行时，显式回退到完全本地的 GroundingDINO + SAM 2.1。
4. GroundingDINO 定位失败时，可使用 Qwen3-VL 输出 bbox/point，再由 SAM 2.1 分割。
5. 禁止调用付费 DINO-X 或 GroundingDINO 1.5/1.6 云 API。
6. 生成关键帧必须重新定位商品，不能直接复用输入图片的 mask 坐标。
7. 使用关键帧 mask 初始化视频目标跟踪。
8. 保存二值 mask、透明前景、bbox、confidence、overlay、商品出现率、跟踪中断和 fallback 原因。
9. 分割失败时，商品一致性必须标记 unavailable，禁止使用错误 mask 给出伪精确分数。

四、结构化输出

定义版本化 Schema：

- product/v1
- intent/v1
- storyboard/v1
- segmentation/v1
- evaluation/v1
- run_manifest/v1

storyboard 的每个事件至少包含：

id、start_s、end_s、camera_motion、subject_action、lighting_action、composition、expected_visual_evidence、forbidden_changes。

保存用户原始 Prompt、VLM 改写 Prompt、rewrite_enabled、负面 Prompt、Prompt 版本和 Prompt hash。VLM 不得虚构品牌、Logo、商品功能和未出现在输入图中的属性。

五、代码可扩展性

定义稳定接口：

- VLMBackend
- ImageGenerator
- VideoGenerator
- ProductSegmenter
- VideoTracker
- MetricEvaluator
- StoryboardEvaluator

模型实现放在 adapters/backends，主流程只调用接口。模型路径、revision、device、dtype、license 和 capabilities 放在 YAML/JSON registry。不要在主流程散落 model_id 判断。

不同模型依赖冲突时使用隔离 Python runtime，不要破坏已经跑通的 VLM、FLUX、LTXV 或 Wan 环境。

真实模型失败必须明确失败。禁止静默切换 mock、付费 API 或其他模型；任何 fallback 都必须写入 manifest 和结果 JSON。

六、商品一致性

保留旧中心椭圆 DINO 作为 legacy 对照，但新默认必须使用真实商品 mask：

- reference/keyframe/video 使用同一 mask crop 规范；
- mask 外合成到统一中性背景；
- DINOv2 提取特征；
- 视频均匀采样 12–16 帧；
- 输出平均、最低、10% 分位、标准差、关键帧相似度；
- 同时输出商品出现率和跟踪中断次数。

对外统一称为“商品一致性”，不要创造 MPIS、STAS 等论文式缩写，也不要把多个子项强行合成难解释的新指标。

七、真正的 Storyboard 遵循度

现有运动量+平滑度+时长指标改名为 legacy_motion_heuristic。

新 Storyboard 评测必须逐事件执行：

- 按事件时间窗口取帧；
- VLM 返回事件是否发生、观察到的起止时间、置信度、证据帧和失败原因；
- push-in 使用商品面积变化辅助判断；
- orbit 使用前景局部特征、横向运动和商品中心稳定性辅助判断；
- lighting sweep 使用前景高光/亮度轨迹辅助判断；
- hero hold 使用末段运动下降和商品稳定性辅助判断；
- 检查事件顺序、时间匹配、硬切、商品消失、复制、容器数量变化和严重变形。

对外只显示一个容易理解的 Storyboard 遵循度，JSON 中保留事件完成、时间与顺序、视觉证据、连续性、违规项和证据帧。权重写入配置，不写死在代码。

若 Qwen3-VL 生成或润色 Storyboard，优先用 InternVL3.5 评审；反之优先使用 Qwen3-VL。评审模型必须记录。

八、完整评测

必须实现并写入 metrics.json：

- JSON Schema 通过率
- 商品属性识别
- OCR 准确率或无文字控制状态
- 分割成功率
- 商品出现率
- 跟踪中断次数
- 商品一致性：DINO mean/min/p10/std
- 输入商品与关键帧相似度
- CLIP text-image
- CLIP text-video
- Storyboard 遵循度及事件子项
- 时序闪烁
- 运动平滑度
- 动态程度
- 帧数、FPS、分辨率
- VLM、图像、视频、评测延迟
- 峰值显存
- 失败率和错误原因

README 主表只展示通用指标类别和含义，详细诊断字段放 JSON。不要把自研实现命名为官方 VBench，除非确实运行了官方代码并记录版本。

九、执行顺序

第一阶段先复用已有 sample-02 / perfume_flacon 与四个唯一视频，不进行昂贵的重新生成：

1. 跑输入、关键帧和视频商品分割；
2. 人工查看 overlay 是否真的只覆盖商品；
3. 计算旧椭圆 DINO 和新真实 mask DINO；
4. 计算新 Storyboard 事件级结果；
5. 如果自动排序和肉眼明显相反，定位分割、采样、VLM 或规则问题，不能只修改权重掩盖。

第二阶段固定输入、canonical storyboard、seed 和输出规格，形成四个唯一媒体组合：

- SDXL+IP-Adapter → LTXV
- SDXL+IP-Adapter → Wan2.2
- FLUX.2-klein → LTXV
- FLUX.2-klein → Wan2.2

VLM 比较独立运行，不复制相同 MP4 冒充 8 个不同视频。只在专门测试 Prompt 润色时让两种 VLM 分别改写，并记录 prompt diff/hash。

第三阶段完成三个简单消融：

- 固定椭圆 vs 真实商品 mask；
- 三帧采样 vs 12–16 帧均匀采样；
- 旧 Storyboard 启发式 vs 新事件级评测。

十一、服务器要求

每次启动前运行：

nvidia-smi --query-gpu=index,name,memory.used,memory.total,utilization.gpu --format=csv,noheader

长任务使用独立 screen/tmux，并通过 tee 将日志保存到 runs/v0.1/logs/。

服务器外网受限。先检查现有模型和 Python/CUDA 环境；缺失依赖或权重在本地暂存并上传，上传后校验 SHA256。服务器确认完整后删除本地暂存副本，避免占用本地磁盘。

禁止提交模型权重、虚拟环境、用户输入媒体、完整生成视频、缓存、日志、token、.env.local 和其他密钥。
