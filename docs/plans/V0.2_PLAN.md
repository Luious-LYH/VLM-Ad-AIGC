# VLM-Ad-AIGC v0.2 修改计划

## 1. 版本定位

v0.2 在 v0.1 的生成与评测能力上增加一个受约束的 Agent 闭环：Agent 读取结构化指标和失败证据，判断问题主要来自 Prompt、关键帧、视频模型还是参数，然后选择有限的修改动作重新生成，直到质量达标或达到预算上限。

对外一句话介绍：

> 在商品广告生成与自动评测链路上增加 Agent，让系统根据商品一致性、Storyboard、文本匹配和时序质量自动选择模型、改写 Prompt、调整参数并完成有限次数的重新生成。

v0.2 的重点不是聊天界面，而是可解释、可复现、不会无限重试的自动决策系统。

## 2. 前置条件

只有 v0.1 满足以下条件后才进入 v0.2：

- 商品分割与跟踪稳定；
- 商品一致性和 Storyboard 评测能输出证据；
- 所有生成任务具有统一请求/响应 Schema；
- Prompt、模型、seed、参数和指标可追溯；
- 不同模型能够通过 registry 最小成本切换；
- 自动指标排序与人工验收至少在小样本上基本一致。

## 3. Agent 闭环

```text
输入商品图与广告需求
        ↓
生成结构化商品信息、Prompt 和 Storyboard
        ↓
选择图像/视频模型并生成候选
        ↓
执行 v0.1 评测
        ↓
Agent 读取分数、失败标签和证据帧
        ↓
判断主要问题类型
        ↓
从受限动作集合选择一次修改
        ↓
重新生成必要阶段，而不是全部重跑
        ↓
新旧候选比较
        ↓
达到阈值 / 无提升 / 预算耗尽后停止
```

## 4. Agent 输入

Agent 不直接读取杂乱日志作为主要依据，而读取统一的 `evaluation_summary.json`：

```json
{
  "run_id": "...",
  "scores": {
    "product_consistency": 0.82,
    "text_alignment": 0.76,
    "storyboard_adherence": 0.55,
    "temporal_stability": 0.91,
    "visual_quality": 0.68
  },
  "failures": [
    "orbit_not_observed",
    "label_changed_at_end"
  ],
  "evidence": [
    "metrics/storyboard.json",
    "masks/overlay.mp4",
    "reports/contact_sheet.png"
  ],
  "generation": {
    "vlm": "qwen3_vl",
    "image_model": "flux2_klein",
    "video_model": "wan22_ti2v_5b",
    "seed": 20260909,
    "prompt_hash": "..."
  },
  "budget": {
    "attempt": 1,
    "max_attempts": 3
  }
}
```

## 5. 问题分类

Agent 只处理有限、容易解释的问题类型：

| 问题类型 | 典型证据 | 优先修改对象 |
|---|---|---|
| 商品外观偏离 | 商品一致性低、Logo/容器数量变化 | 图像 Prompt、参考强度、图像模型、seed |
| 关键帧构图不合格 | 主体过小、裁切、背景错误 | 图像 Prompt、宽高比、图像模型 |
| Storyboard 未完成 | 某事件缺失、时间顺序错误 | 视频 Prompt、事件描述、视频模型 |
| 视频闪烁或跳变 | 时序稳定性低、mask 轨迹突变 | 视频参数、视频模型、运动强度 |
| 运动不足 | dynamic degree 低、镜头近似静止 | 视频 Prompt、motion strength、视频模型 |
| 文本需求不匹配 | CLIP/VLM 文本匹配低 | Prompt 润色与场景描述 |
| 生成失败/OOM | 错误类型、峰值显存 | 分辨率、帧数、offload、模型切换 |

## 6. 受限动作集合

为避免 Agent 随意修改系统，动作必须结构化：

```text
rewrite_image_prompt
rewrite_video_prompt
strengthen_identity_constraints
simplify_storyboard_event
adjust_reference_strength
adjust_motion_strength
change_seed
switch_image_model
switch_video_model
reduce_resolution_or_frames_on_oom
stop_and_request_human_review
```

每轮只允许一个主要动作和最多一个配套参数调整。所有修改都写入 `decision.json`：

- 修改前状态；
- 发现的问题；
- 证据；
- 选择动作；
- 预期改善指标；
- 实际变化；
- 是否保留新候选。

## 7. 最小重跑策略

- 商品理解错误：只重跑 VLM 及其下游。
- 关键帧不合格：重跑图像与视频阶段。
- 关键帧合格但视频失败：只重跑视频和视频评测。
- 仅评测失败：只重跑评测，不重新生成媒体。
- OOM：先调整 offload/分辨率/帧数，再考虑模型切换。

这样既减少 GPU 时间，也让 Agent 的决策更容易解释。

## 8. 综合质量分

v0.2 可以增加一个通用的“综合质量分”用于候选排序，但不是论文指标，也不取代各子项。

默认建议：

```text
综合质量分 =
30% 商品一致性
+ 25% Storyboard 遵循度
+ 20% 时序稳定性
+ 15% 文本匹配
+ 10% 画面质量
```

规则：

- 分项原始结果必须保留；
- 权重写入配置，不写死在代码；
- 商品消失、复制、严重变形等硬失败直接触发淘汰，而不是靠加权平均掩盖；
- 模型间比较使用相同输入、seed 策略和输出规格；
- 人工选择可以覆盖自动排序，并记录覆盖原因。

这是本项目唯一建议新增的综合指标，名称直接使用“综合质量分”，不创建缩写。

## 9. Prompt 优化策略

Prompt 被拆成可局部修改的字段：

```text
identity_constraints
scene_description
camera_motion
subject_action
lighting_action
style
negative_constraints
```

Agent 只能修改与失败类型相关的字段。例如商品一致性低时，禁止顺手重写广告风格；StoryBoard 环绕缺失时，只增强对应事件和运动描述。

保留每轮 Prompt diff，防止无法解释“为什么变好”。

## 10. 模型选择策略

第一版使用可解释规则，不训练路由模型：

| 条件 | 推荐动作 |
|---|---|
| 需要快速预览 | LTXV-2B distilled |
| 需要主要质量结果 | Wan2.2 TI2V-5B |
| 参考商品身份保持不足 | SDXL+IP-Adapter 与 FLUX 互换并比较 |
| 关键帧生成速度优先 | FLUX.2-klein-4B |
| VLM 输出 Schema 不稳定 | 切换另一个 VLM 或执行结构化修复 |
| 显存不足 | 开启 offload、降低规格或切换轻量模型 |

等积累足够运行数据后，才考虑学习型路由器或奖励模型。

## 11. 停止条件与成本控制

每个请求默认：

- 最多 3 轮；
- 最多生成 2 个关键帧候选；
- 每轮最多生成 2 个视频候选；
- 达到配置阈值后立即停止；
- 连续两轮综合质量分无明显提升时停止；
- 出现分割不可用、模型连续失败或证据冲突时交给人工。

服务器只有 3×3090 且无 NVLink，Agent 调度应使用独立 worker，不假设显存自动合并。

## 12. 代码结构建议

```text
services/aigc-service/app/agent/
  controller.py          闭环状态机
  diagnosis.py           指标到问题类型映射
  actions.py             受限动作定义
  policy.py              规则策略
  stopping.py            阈值、预算与停止条件
  schemas.py             decision/iteration/session Schema

configs/v0.2/
  agent-policy.yaml
  quality-thresholds.yaml
  model-routing.yaml

runs/v0.2/<session_id>/
  session.json
  iteration-01/
  iteration-02/
  final-selection.json
```

Agent 控制器依赖 v0.1 的统一接口，不直接调用某个具体模型脚本。

## 13. 实验设计

### 对比组

- 无 Agent：固定模型、Prompt 和 seed，只生成一次。
- Prompt-only Agent：只能修改 Prompt。
- Prompt + parameter Agent：可修改 Prompt、seed 和有限参数。
- Full Agent：可切换图像/视频模型并执行有限次数重试。

### 需要报告

- 首次生成综合质量分；
- 最终综合质量分；
- 各分项变化；
- 平均迭代次数；
- 成功率；
- 总耗时和 GPU 时间；
- Agent 动作分布；
- 自动选择与人工选择一致率。

先使用 3 个商品 × 3 个 Prompt，不需要为了简历项目做大规模数据集。

## 14. v0.2 验收标准

- Agent 能从结构化指标识别主要失败类型。
- 每轮决策都有证据和 Prompt/参数 diff。
- 能按依赖关系最小化重跑阶段。
- 最多 3 轮后可靠停止，不出现无限循环。
- 至少支持 Prompt 修改、seed 调整和图像/视频模型切换。
- 对一组固定样本，自动优化后的结果由人工确认多数不差于首次生成。
- 自动排序结果、人工选择和成本全部可追溯。
- 任何模型失败或 fallback 都显式记录。
