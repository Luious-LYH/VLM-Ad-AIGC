# VLM-Ad-AIGC v0.1 修改计划

## 1. 版本定位

v0.1 的目标是把当前模型对比工程整理为一个真正可演示的端到端项目：用户提供一张商品图片和一段需求文本，系统理解商品、生成广告关键帧和视频，并输出可以追溯到具体帧和商品区域的质量评测结果。

对外一句话介绍：

> 输入一张商品图和广告需求，由 VLM 生成结构化商品信息与 Storyboard，再调用图像扩散模型和视频扩散模型生成短广告，最后通过商品分割、DINO/CLIP、VLM 和时序视觉指标完成自动评测。

v0.1 不实现 Agent 自动迭代，不新增前端页面，不训练基础模型，也不一次引入大量视频质量模型。

## 2. 目标与非目标

### 必须完成

- 支持商品 PNG/JPG 与用户 Prompt 输入；优先利用 PNG Alpha 前景。
- Qwen3-VL-4B-Instruct 与 InternVL3.5-8B-HF 使用统一接口完成商品理解和可选 Prompt 润色。
- 输出结构化 `product.json`、`intent.json` 和 `storyboard.json`。
- SDXL 1.0 + IP-Adapter 与 FLUX.2-klein-4B 使用统一关键帧接口。
- LTXV-2B distilled 与 Wan2.2 TI2V-5B 使用统一视频接口。
- 引入真实商品分割与视频跟踪，替换固定中心椭圆作为默认 DINO 区域。
- 真正按 Storyboard 的时间段和动作要求进行评测。
- 每次运行保存模型、Prompt、seed、显存、延迟、输入哈希、mask 和指标。
- 使用已有 `sample-02 / perfume_flacon` 完成真实服务器 smoke test。

### 本版本不做

- 不做 Agent 自动改 Prompt、调参或重试。
- 不做新的前端/后端交互页面。
- 不接入付费模型或静默云端回退。
- 不全量接入 VBench、VideoScore 等重型评测套件。
- 不使用 HunyuanVideo 作为默认对比模型；保留历史文件但不进入 v0.1 主实验。
- 不创造论文式指标名称或缩写。

## 3. 端到端流程

```text
商品图 + 用户 Prompt
        │
        ├─ 有 Alpha：直接得到参考商品 mask
        └─ 无 Alpha：分割模型生成参考商品 mask
        ↓
VLM 商品理解
        ↓
product.json + intent.json
        ↓
可选 Prompt 润色 + 结构化 Storyboard
        ↓
SDXL+IP-Adapter / FLUX.2-klein 生成关键帧
        ↓
在关键帧中重新定位并分割商品
        ↓
LTXV / Wan2.2 生成视频
        ↓
从关键帧向视频传播商品 mask
        ↓
商品一致性 + 文本匹配 + Storyboard + 时序质量 + 工程性能
        ↓
metrics.json + report.md + mask/证据帧/overlay
```

## 4. 模型角色与接口

| 角色 | 当前模型 | 默认选择 | 切换原则 |
|---|---|---|---|
| VLM | Qwen3-VL-4B-Instruct、InternVL3.5-8B-HF | Qwen3-VL | 都返回同一结构化 Schema；模型差异只留在 adapter 中 |
| 商品分割 | SAM 3.1；回退为本地 GroundingDINO + SAM 2.1 | 先 smoke test SAM 3.1 | 权重、环境或稳定性失败时显式回退并记录原因 |
| 图像生成 | SDXL 1.0 + IP-Adapter、FLUX.2-klein-4B | FLUX.2-klein | FLUX 用于主要展示，SDXL 作为成熟参考控制基线 |
| 视频生成 | LTXV-2B distilled、Wan2.2 TI2V-5B | Wan2.2 | Wan2.2 作为质量路线，LTXV 作为快速路线 |
| 商品特征 | DINOv2 | DINOv2 | 只对真实商品 mask 内的裁剪区域提特征 |
| 文本匹配 | CLIP | CLIP | 保留现有快速、可复现的文本图像相似度 |
| Storyboard 评审 | Qwen3-VL / InternVL3.5 + 视觉规则 | 交叉评审 | 尽量不让生成 Storyboard 的 VLM 独立给自己打分 |

建议定义以下稳定接口：

```text
VLMBackend
ImageGenerator
VideoGenerator
ProductSegmenter
VideoTracker
MetricEvaluator
StoryboardEvaluator
```

主流程只面向接口，模型路径、设备、dtype、revision 和能力写入配置文件。禁止在主流程散落大量 `if model_id == ...`。

## 5. 输入、Schema 与 Prompt

### 输入约定

- `product_image`：PNG/JPG；PNG Alpha 有效时优先使用。
- `user_prompt`：用户对场景、风格、动作、镜头或广告目标的描述。
- `rewrite_prompt`：布尔值，默认开启但允许关闭做消融。
- `vlm_model`、`image_model`、`video_model`、`seed`：都由配置选择。

### VLM 输出

`product.json`：

- 类别、颜色、材质、表面质感；
- 包装结构、瓶盖/泵头、容器数量；
- OCR 文本与置信度；
- 必须保持不变的身份属性。

`intent.json`：

- 用户希望表达的广告风格、场景、镜头、动作；
- 用户明确要求与系统推断内容分开保存；
- 不允许 VLM 添加不存在的品牌名、Logo 或商品功能。

`storyboard.json`：

```json
{
  "schema_version": "storyboard/v1",
  "duration_seconds": 4.0,
  "events": [
    {
      "id": "event_01",
      "start_s": 0.0,
      "end_s": 0.8,
      "camera_motion": "macro_push_in",
      "subject_action": "product_static",
      "lighting_action": "soft_highlight",
      "expected_visual_evidence": [
        "product_scale_increases",
        "product_center_stable"
      ],
      "forbidden_changes": [
        "duplicate_product",
        "shape_mutation"
      ]
    }
  ]
}
```

必须同时保存原始 Prompt、VLM 改写 Prompt、负面 Prompt、Prompt 版本与哈希，以便 v0.2 精确修改。

## 6. 商品分割与跟踪

### 推荐路径

1. 输入是透明 PNG：Alpha 直接成为参考 mask，并做面积、连通域和边界检查。
2. 输入无 Alpha：优先用 SAM 3.1 文本/示例提示分割商品。
3. SAM 3.1 无法部署：使用本地 GroundingDINO 定位商品，再用 SAM 2.1 得到 mask。
4. GroundingDINO 失败：让 VLM 返回 bbox/point，交给 SAM 2.1。
5. 在生成关键帧中重新定位商品，不能直接套用输入图 mask。
6. 以关键帧 mask 初始化视频跟踪，将 mask 传播到采样帧或全部帧。

### 输出

- 原始二值 mask；
- 透明商品前景 PNG；
- bbox、面积比例、置信度；
- 视频 mask overlay；
- 商品出现率和跟踪中断次数；
- 使用的主模型、回退模型与回退原因。

如果分割错误，不允许继续输出看似精确的商品相似度；结果应标记为 `unavailable` 或 `segmentation_failed`。

## 7. 商品一致性评测

废弃固定中心椭圆作为默认方案，但保留旧结果用于前后对比。

新流程：

1. 对输入商品、关键帧商品和视频商品使用真实 mask。
2. 按 bbox 裁剪并保留固定 margin。
3. mask 外统一合成到中性背景。
4. 使用同一 DINOv2 预处理得到 embedding。
5. 视频均匀采样 12–16 帧，不再只取首、中、尾三帧。
6. 计算输入商品与每个视频商品区域的余弦相似度。

README 中只展示容易理解的“商品一致性”；`metrics.json` 内保存：

- 平均相似度；
- 最低相似度；
- 10% 分位相似度；
- 相似度标准差；
- 关键帧商品相似度；
- 商品出现率；
- 跟踪中断次数。

这些子项是为了定位问题，不再合成为自定义论文指标。

## 8. Storyboard 遵循度

现有的运动量、平滑度和时长分数改名为 `legacy_motion_heuristic`，不再冒充 Storyboard 遵循度。

新的 Storyboard 评测按每个 `events[]` 执行：

1. 根据目标起止时间采样该事件对应帧。
2. VLM 返回事件是否出现、观察到的时间段、置信度、证据帧和失败原因。
3. 视觉规则提供辅助证据：
   - push-in：商品 bbox/mask 面积随时间增加；
   - orbit：商品中心相对稳定，同时前景局部特征和横向运动连续变化；
   - lighting sweep：商品轮廓稳定，前景高光位置或亮度连续变化；
   - hero hold：结尾运动明显下降，商品位置和形态稳定。
4. 检查事件是否按顺序发生、是否落入目标时间段。
5. 检查硬切、商品消失、复制、容器数量变化和严重变形。

对外仅展示一个 `Storyboard 遵循度`，但 JSON 中保留：

- 每个事件的完成分；
- 时间匹配分；
- 顺序是否正确；
- 视觉证据分；
- 违规项和证据帧。

最终分数使用配置化、容易解释的权重：

```text
Storyboard 遵循度 =
45% 事件是否完成
+ 25% 时间与顺序
+ 20% 视觉运动证据
+ 10% 转场连续性
- 明确违规扣分
```

这是自动代理分数，不等于人工审美评分。报告必须同时提供证据帧或 contact sheet。

## 9. 完整评测但保持易讲解

README 主表只展示以下核心指标：

| 指标 | 回答的问题 |
|---|---|
| 商品理解 | VLM 是否正确读懂商品属性和文字？ |
| 商品分割与跟踪 | 系统是否持续找到了真正的商品区域？ |
| 商品一致性 | 视频中的商品是否仍像输入商品？ |
| 文本匹配 | 关键帧和视频是否符合广告描述？ |
| Storyboard 遵循度 | 指定动作是否按时间顺序完成？ |
| 时序稳定性 | 是否存在闪烁、跳变和不平滑运动？ |
| 画面质量 | 是否清晰、可用、没有明显生成异常？ |
| 工程性能 | 延迟、显存、失败率和输出规格如何？ |

详细 JSON 可以继续包含 Schema、属性准确率、OCR、CLIP-I/CLIP-V、帧间变化、FPS、分辨率等，不要求面试时逐个背诵。

## 10. 实验设计

### 第一阶段：使用现有视频验证评测链路

- 样本：`sample-02 / perfume_flacon`。
- 不重新生成视频，先对已有四个唯一视频完成真实分割、跟踪、商品一致性和 Storyboard 评测。
- 输出旧椭圆 DINO 与真实 mask DINO 的对比。
- 人工检查 mask overlay 和指标排序是否符合肉眼判断。

### 第二阶段：四个唯一生成组合

固定同一输入、canonical storyboard、seed 和输出规格：

| 图像模型 | 视频模型 |
|---|---|
| SDXL + IP-Adapter | LTXV-2B distilled |
| SDXL + IP-Adapter | Wan2.2 TI2V-5B |
| FLUX.2-klein-4B | LTXV-2B distilled |
| FLUX.2-klein-4B | Wan2.2 TI2V-5B |

VLM 理解能力独立比较，不复制相同 MP4 形成虚假的 8 个媒体产物。专门研究 Prompt 润色影响时，再打开 `rewrite_prompt` 并记录 Prompt 差异。

### 第三阶段：小消融

- 固定椭圆 vs 真实商品 mask；
- 首中尾三帧 vs 均匀 12–16 帧；
- 旧 Storyboard 启发式 vs 新事件级 Storyboard 评测；
- Prompt 原文 vs VLM 润色，仅选择一个稳定模型组合生成。

## 12. 三天执行顺序

### 第一天：结构与分割

- 冻结 Schema 和 adapter 接口；
- 检查并复用服务器环境；
- smoke test SAM 3.1；失败则部署 SAM 2.1 + 本地 GroundingDINO；
- 输出输入图、关键帧和视频的 mask/overlay。

### 第二天：评测

- 完成真实 mask DINO；
- 完成事件级 Storyboard 评测；
- 保留 CLIP 与基础时序指标；
- 在现有 sample-02 四个视频上调试。

### 第三天：真实生成与交付

- 跑四个唯一模型组合或复用已验证产物；
- 生成 comparison JSON/Markdown；
- 完成 README、运行说明和消融结果；
- 做可解码性、Schema、失败路径与 Git 内容检查。

## 13. 验收标准

- 一个 CLI 命令可以从商品图和 Prompt 运行到完整报告。
- 输入商品、关键帧和视频均有真实商品 mask 或明确失败状态。
- 商品一致性基于真实 mask 和不少于 12 个均匀视频采样帧。
- Storyboard 遵循度包含事件级结果、时间证据与证据帧。
- 两种 VLM、两种图像模型和两种视频模型都通过独立 smoke test。
- 至少保留四个唯一视频组合，不能复制相同 MP4 冒充新结果。
- `manifest.json` 记录模型版本、seed、Prompt/hash、输入 SHA256、延迟、显存和产物路径。
- README 第四张表完整说明所有评测指标。
- 测试、服务器日志和精选结果可复现。
